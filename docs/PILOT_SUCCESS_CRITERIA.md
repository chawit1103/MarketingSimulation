# Pilot Success Criteria

Updated: 2026-05-17

Use this document to define whether a controlled paid pilot succeeded.

## Required Product Framing

3C Simulator outputs are decision-support estimates. They do not guarantee exact sentiment, conversion, revenue, ROI, crisis probability, or market share.

## Success Metrics

| Area | Success Signal |
| --- | --- |
| Clarity | User understands Demo Mode, Local Estimate, Live Backend, and Backend Verified labels. |
| Decision value | User can name one decision the output helped them make. |
| Trust | User can explain assumptions, limitations, and next validation step. |
| Workflow fit | User can complete brief review, dashboard review, and action-plan review with limited help. |
| Commercial value | Sponsor says the output could support leadership review, client pitch, or campaign revision. |
| Data safety | No PII, raw CRM records, live integrations, or secrets were used. |

## Minimum Acceptance Criteria

A pilot is successful only if:

- At least one approved scenario reaches an actionable recommendation.
- The customer accepts the source/provenance labeling approach.
- The final deck is useful for an internal meeting or client discussion.
- No data-handling rule is violated.
- The customer identifies a concrete next step: revise campaign, validate further, expand pilot, or stop.

## Evidence To Collect

- Scenario name or anonymized scenario code.
- Role of reviewer.
- Brief Quality Score before simulation.
- Source mode shown.
- Top risk driver.
- Top recommended action.
- Customer quote about usefulness or confusion.
- Follow-up validation step selected by the customer.
- Whether the customer would pay for another scenario.

## Failure Signals

- User treats outputs as guaranteed predictions.
- Source/provenance labels are ignored or misunderstood.
- Customer needs raw CRM, PII, or live integrations to see value.
- Action Plan feels generic and does not change a decision.
- Export is not credible enough for leadership or client review.

## Go/No-Go After Pilot

| Decision | Criteria |
| --- | --- |
| Expand pilot | Customer wants more scenarios and accepts data boundaries. |
| Convert to consulting package | Customer values guided interpretation more than self-serve software. |
| Product gap follow-up | Customer sees value but requires missing workflow, evidence, or controls. |
| Stop | Customer needs production SaaS, live integrations, or guaranteed predictions immediately. |
