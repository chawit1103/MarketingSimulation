# Pilot Exit Checklist

Updated: 2026-05-17

Use this checklist at the end of every controlled paid pilot.

## Completion Checklist

- [ ] All scenarios used approved, non-PII input data.
- [ ] No raw CRM records, customer lists, provider secrets, or live integrations were used.
- [ ] Source/provenance labels remained visible in UI, screenshots, exports, and decks.
- [ ] Outputs were described as estimates, not guaranteed predictions.
- [ ] Customer reviewed assumptions and limitations.
- [ ] Customer selected a next validation step.
- [ ] Pilot artifacts were delivered or deleted according to customer approval.

## Business Review

Record:

- Sponsor name or role.
- Use case.
- Number of scenarios reviewed.
- Most useful section.
- Most confusing section.
- Decision influenced.
- Requested follow-up.
- Willingness to pay for next step.

## Data Exit

Decide one:

- Delete pilot artifacts.
- Retain anonymized scenario outputs for agreed period.
- Retain exported deck only.
- Transfer artifacts to customer and delete local copies.

Do not retain customer data by default.

## Commercial Exit Options

| Outcome | Next Step |
| --- | --- |
| Strong value | Propose Strategy Pilot expansion or executive workshop. |
| Value but workflow gaps | Propose scoped product improvement or consulting package. |
| Data/security blocker | Pause until requirements can be met without production-risk shortcuts. |
| No clear value | Close pilot and document learning. |

## Final Disclosure

Confirm in the exit note:

- Local demo remains ready.
- Controlled private pilot remains conditional.
- Public pilot, public internet exposure, and production customer deployment remain blocked until documented readiness gates are completed.
